# 探索地點與全島寶箱探查（更新至 0.5.3）

## 新月島探索地點

僅提供新月島南部 Territory 1252、Map 967 島上的 12 處固定探索地點，預設關閉。0.5.1 起依使用範圍排除塔內第 30 處「避世書庫」。位置與名稱來自本機繁中客戶端 `2026.09.14.0000.0000`。

| 紀錄編號 | 名稱 |
|---|---|
| 05 | 調查隊營地 |
| 07 | 圓頂城塞 |
| 09 | 蜃景灘 |
| 12 | 南部丘陵 |
| 13 | 岩窟後街 |
| 15 | 禁忌廢都 |
| 18 | 古樹濕原 |
| 19 | 階梯殿堂 |
| 21 | 高層住宅遺址 |
| 22 | 巨像兵工房遺址 |
| 23 | 放浪神聖域遺址 |
| 24 | 大聖火台遺址 |

在 `/crescent` 勾選「島上探索筆記」，從「地點清單」單點插旗，或按「規劃巡查路線」。若只想跑探索地點，可取消其他種類。探索點不受物件顯示範圍限制，也不因未載入而被路線移除；開啟「塔內／獎勵」寶箱開關也不會加入避世書庫。

這些是新月島探索紀錄地點，並非一般地區的 `Adventure` 探索筆記。工具檢查本機 340 筆 Adventure，均不屬於新月島。改以 `MKDLore.Unknown4` 對應島內 LGB `EventObject.InstanceId`，保留實際 XYZ、高度、地圖及紀錄名稱。蜃景鎮第 02 處不在島內場景，排除。任務、怪物等非地點紀錄不加入。北區沒有本機可核對資料，本版不臆測其探索點。

0.5.3 新增「只顯示未探索的筆記地點」，預設勾選，探索主開關仍維持原設定。清單、場景提示、單點插旗、規劃及傳送接續都使用相同條件。取消勾選可查看遊戲已完成的固定地點；本輪手動已巡查者仍隱藏，需清除巡查紀錄才能再次巡查。

角色資料載入且身分匹配時，每 0.5 秒在遊戲框架更新中，以 `IUnlockState.IsMKDLoreUnlocked(row)` 讀取每個 `MKDLore` 紀錄。完成地點自動離開待巡路線；若是首站，自動下一站設定開啟時會在互動結束後插下一旗，魔法罐搜尋期間延後。刪除中間站後不畫虛構連線，可重新規劃剩餘順序；下一站仍重新查詢目前步行路徑。計算中的舊結果不能重新加入已完成筆記。

初次讀取失敗、資料缺漏或角色尚未載入，狀態為未知，未探索篩選暫不顯示這些點；不以 `false` 預設值冒充未完成。已取得有效結果後短暫讀取失敗會保留本角色上次快照，介面顯示更新暫停。同角色已觀察到的完成狀態不回退；登出、換角色、場次重建或重載插件清除快照再讀，同島傳送則保留。此資料只存在記憶體，沒有寫入角色完成紀錄或外傳角色身分。

「已巡查」是獨立手動狀態，按下一站不會解鎖遊戲筆記。清除巡查紀錄也不會讓遊戲已完成筆記回到未探索清單。全部 12 處完成時，未探索數為 0，寶箱巡查不受影響。

本機 SDK 中繼資料核對確認，繁中 API 13 的查詢實際使用 `MKDLore.Unknown2` 解鎖連結，並先檢查 `IPlayerState.IsLoaded`；不使用猜測的記憶體偏移。上游 [Dalamud 解鎖服務](https://github.com/goatcorp/Dalamud/blob/master/Dalamud/Game/UnlockState/UnlockState.cs) 對應欄位名稱為 `UnlockLink`。此服務在 API 13 標為 experimental，編譯診斷只在注入宣告處局部抑制；本版限定已核對的繁中 SDK，不宣稱跨版本相容。[本機欄位核對](audit/exploration-unlocks.txt) 記錄 12 個非零解鎖編號。實際遊戲角色的完成結果仍待對照驗收。

可重現唯讀核對：

```powershell
dotnet run --project tools/GameDataAudit/GameDataAudit.csproj -c Release -- 'C:/Program Files/USERJOY GAMES/FINAL FANTASY XIV TC/game/sqpack' --sightseeing
```

輸出 `.references/southhorn-exploration.json`，保留原始核對的 13 個場景地點；發行內建快照 `CrescentCompass/Data/SouthHorn/exploration_locations.json` 排除塔內第 30 處後提供 12 處。精簡稽核輸出保存在 [探索與探查稽核](audit/exploration-survey-audit.txt)，保留原始資料，不將範圍調整誤寫為來源缺失。

## 全島寶箱範圍與限制

使用者要求的是「整張島自己可開的寶箱」，而非可視範圍。目前**尚無已驗證的完整個人寶箱座標／開箱權限介面**，因此本版不將任何替代清單標為完整答案。

| 選單 | 行為與限制 |
|---|---|
| 全島已知位置（預設） | 只收錄本場曾偵測為可選取的物件；離開載入範圍仍保留，標示「曾看見 · 待確認」。未曾發現的固定候選點不加入。不保證個人權限或遠處仍存在。 |
| 目前可選取 | 地點清單僅列已載入、可選取、尚未確認開啟的物件；0.5.2 起已規劃站點離開範圍仍保留，等待到場確認，不算完成。 |
| 全島候選巡查 | 可另外巡查固定候選位置；不代表此玩家目前有箱或能開箱。 |

0.4.3 起魔法罐搜尋獨立於以上物件範圍。取得狀態、收到方向／加碼提示或現身寶箱時，預設自動更新搜尋位置與旗標；候選座標始終標示尚未確認。一般寶箱清單仍遵循原本的篩選。

所有模式排除已確認開啟、手動完成或自動略過的站點，探索地點使用獨立選項。0.4.1 新增開箱與近距離空點自動下一站；可選取模式會暫留近距離首站等待空點確認，詳細範圍見 [README](../README.md)。原生遊戲旗標一次只能有一個；全路線顯示於插件示意圖與清單。

個人寶箱探查取繁中系統頻道 57 的 `LogMessage` 10965／10966 文字範本，解析銀箱、銅箱數量並記錄時間。API 13 未提供新版的 LogMessage ID 事件，故採系統頻道加完整文字匹配，拒絕說話、隊伍或前綴引用。未收到訊息時顯示未知，不當作零。遊戲回報無寶箱才顯示零。

**數量是最後一次探查快照，不是即時剩餘箱數。** 開箱不自動減數，請再次使用遊戲內探查能力更新。它不包含座標，亦不能用數量決定 60 個銅箱候選中哪些屬於此玩家。魔法罐、兔子及塔內獎勵不計入這張銀／銅箱快照。

確認離島、登出、分流改變會清除數量與已知位置，避免沿用別場資訊。同島同分流傳送保留巡查紀錄、路線與數量快照，落地後續巡；快照並非新位置的即時探查結果。遊戲內驗收表列於 [IN_GAME_CHECKS.md](IN_GAME_CHECKS.md)。
